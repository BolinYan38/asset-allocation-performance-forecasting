# calendar_recovery.py：恢复训练集匿名日期

我们结合市场开休市日历、成交量报告模式和策略收益窗口重合，恢复匿名日期对应的真实日期。`calendar_recovery.py` 实现候选日期筛选与日期关系合并，入口为 `CalendarRecovery.recover()`。

我们先为每个匿名日期建立真实日期候选集合，再寻找匿名日期之间相隔多少个市场交易日，最后把这些关系作用到候选集合上。候选只剩一天时，该匿名日期就完成定位；仍有多个候选时，保留全部兼容方案。

## 1. 入口与执行顺序

```python
mapping, report = CalendarRecovery(device).recover(raw, sessions)
```

`device` 指计算设备；`raw` 是匿名日期数据；`sessions` 是各市场的真实交易日期字典。返回的 `mapping` 保存日期候选映射，`report` 保存恢复情况统计。

`raw` 中参与本文件计算的字段如下：

| 字段 | 含义 |
|---|---|
| `date_names` | 匿名日期名称列表，例如 `DATE_0001` |
| `dates` | 每条记录对应的匿名日期编号，即其名称在 `date_names` 中的位置 |
| `allocation_names` | 策略名称列表 |
| `allocations` | 每条记录对应的策略编号 |
| `groups` | 每条记录所属的市场组别 |
| `returns` | 每条记录的20日历史策略收益，按最早到最近排列 |
| `volumes` | 每条记录的20日历史成交量字段，顺序与收益一致 |
| `train_mask` | 每条记录是否属于训练集的布尔标记 |

我们将策略组别 `GROUP` 视为市场标识，并按第1至4组分别对应上海、韩国、日本、香港的关系组织 `sessions`。`calendar_recovery.py` 在这一市场对应关系下，结合历史特征与真实交易日历恢复日期。

`recover()` 的执行顺序为：

```text
CalendarInputs(raw)             整理策略、训练日期和报告模式
创建 calendar                  建立真实自然日搜索范围
session_positions(...)         查询每个自然日在各市场的位置
inputs.candidate_domains(...)  筛选每个匿名日期的初始候选
FunctionalCalendarForest(...)  初始化独立关联组
inputs.edges(...)              根据收益窗口生成日期关系
forest.add(edge)               按顺序合并并筛选候选方案
forest.domains()               取出最终候选
返回 mapping、report
```

其中，`inputs` 是整理后的输入对象，`forest` 是管理关联组的对象，`edge` 是一条匿名日期之间的前后间隔关系，具体结构在后文说明。

## 2. CalendarInputs：整理策略与匿名日期

### 2.1 区分训练日期和查询日期

`CalendarInputs.__init__()` 根据 `train_mask`，分别提取训练记录和非训练记录出现过的匿名日期编号，保存为 `training_dates` 和 `query_dates`。

匿名日期编号只用于数组索引，不代表时间先后。真实先后关系在后续步骤中恢复。

### 2.2 选择用于定位的策略

我们为每条策略统计两个量：`counts` 是该策略在训练集中的记录数，`reporting` 是这些记录中最近一天成交量字段有值的记录数。

筛选标记 `stable` 定义为：

```python
self.stable = (counts > 500) & (reporting < 0.9 * counts)
```

通过筛选的策略需要有超过500条训练记录，而且最近一天成交量的报告比例低于90%。有值由 `np.isfinite()` 判断，零值也计为有值。

我们要求策略具有超过500条训练记录，以提供足够的日期覆盖，并通过报告比例条件选出最新成交量存在缺报的策略。我们采用“周一集中更新最新成交量”的假设，将这批策略的集中报告情况用于星期筛选。同一批策略也参与第6节的收益窗口匹配。

`allocation_groups` 记录每条策略所属的市场组别，供后续逐市场选取策略。

## 3. 创建自然日范围与市场交易日位置

`recover()` 创建的真实日期搜索范围为2000年2月1日至2025年12月31日，保存为 `calendar`：

```python
calendar = np.arange(
    np.datetime64("2000-02-01"),
    np.datetime64("2026-01-01"),
)
```

结束日期不包含在数组中。随后调用：

```python
positions = session_positions(calendar, sessions)
```

`positions` 是字典：键为市场组别，值为与 `calendar` 等长的整数数组。对于每个自然日，市场开市时保存它在该市场交易日期数组中的下标，休市时保存 `-1`。

`session_positions()` 先用 `np.searchsorted()` 查找插入位置，再核对对应交易日期是否等于所查自然日。这样可以区分真正的交易日与落在两个交易日之间的休市日。

后文区分三种编号：

| 编号 | 含义 |
|---|---|
| 匿名日期编号 | 匿名名称在 `raw.date_names` 中的位置 |
| 自然日下标 | 真实日期在 `calendar` 中的位置 |
| 市场交易日下标 | 真实日期在某个市场的 `sessions` 数组中的位置 |

候选集合保存自然日下标；计算相隔几个交易日时，使用市场交易日下标。

## 4. candidate_domains：筛选初始候选日期

`inputs.candidate_domains()` 逐个处理匿名日期，应用两条条件。

### 4.1 当天出现的市场必须全部开市

先找出该匿名日期出现过哪些 `groups`，然后对这些市场的开市标记逐次取交集。

例如，某匿名日期同时有日本组和香港组记录，候选日期必须满足日本与香港当天都开市。当天没有出现的市场，不参与这次筛选。

### 4.2 按成交量报告模式区分周一与非周一

先取出当前匿名日期中通过 `stable` 筛选的策略记录，保存为 `reporters`。再判断：

```python
is_monday = (
    len(reporters) > 0
    and np.isfinite(raw.volumes[reporters, -1]).mean() > 0.5
)
```

`is_monday` 是当前匿名日期是否被判为周一的布尔标记。所选策略超过一半报告了最近一天成交量时，只保留周一；其余情况只保留非周一。恰好50%或没有符合条件的记录时，也归入非周一。

我们将最新成交量集中报告作为周一的日期标记。“周一”对应关系在这里作为固定规则使用。

筛选结果保存为 `domains`，即按匿名日期编号排列的候选数组列表。若某个匿名日期没有任何候选，函数返回错误。

## 5. 初始化 FunctionalCalendarForest

建立候选集合后，我们创建 `FunctionalCalendarForest`，用于维护匿名日期之间的关联组。

初始化时，每个匿名日期独立成组。对象保存以下状态：

| 属性 | 含义 |
|---|---|
| `owners` | 每个匿名日期所属的关联组编号 |
| `components` | 外层键为关联组编号，内层键为匿名日期编号，内层值为候选自然日下标数组 |
| `maps` | 按市场交易日移动日期的查询数组缓存 |
| `accepted` | 接受的关系数量 |
| `rejected` | 拒绝的关系数量 |

同一关联组内，各匿名日期的候选数组等长，因为我们只会把认定有前后顺序关系的匿名组放到同一关联组。**同一列代表一套共同成立的日期方案**。后续筛选和合并始终按整列进行。

## 6. edges：从收益窗口恢复日期间隔

### 6.1 构造固定策略列的收益数组

`CalendarInputs.panel` 首次访问时创建并缓存一个数组，三个维度依次为匿名日期、策略、20个历史日。记录中未出现的“匿名日期与策略”组合，先保留为 `NaN`，即缺失值。

`edges()` 逐市场取出属于该市场、且通过 `stable` 筛选的固定策略名单，保存为 `selected`。名单使用固定随机种子排列，随后对所有日期使用相同列顺序。

某个匿名日期缺少一条所选策略时，仍保留该策略列，并在匹配时填零。因此，即使两个日期实际出现的策略数量不同，仍能得到等长的比较向量。

收益数组经时间反转、维度调整和缺失填零后，保存为 `windows`，维度依次为：

```text
匿名日期 × 20个历史日（最近到最早）× 固定策略列
```

### 6.2 确定查询日期和参考日期

`present` 标记某匿名日期在当前市场是否至少有一条所选策略提供了最近一天收益。

在 `recover()` 使用的默认模式下，`queries` 是满足 `present` 的全部匿名日期，表示需要寻找关系的日期；`references` 是满足 `present` 的训练集匿名日期，表示允许匹配的参考日期。

`edges()` 也支持 `query_only=True`，将查询和参考均限制为官方测试日期，供后续日期对齐模块调用。

### 6.3 SuccessorWindowMatcher.match：错开窗口后比较余弦相似度

`gap` 表示正在尝试的市场交易日间隔。`CalendarRecovery` 默认从1到5依次尝试，相似度门槛 `threshold` 默认为0.92。

假设甲比乙早一个交易日，甲的20日窗口与乙的20日窗口应有19日重合。由于 `windows` 按最近到最早排列，我们比较甲最近的19天与乙跳过最近一天后的19天。

匹配器中的 `values` 是传入并放到指定设备上的收益数组。一般间隔下，两边对应切片为：

```python
values[甲, :20-gap]
values[乙, gap:]
```

匹配器把“重合历史日 × 策略”展开为向量，再将每个非零向量除以自身长度，使其长度为1。这里的长度指各元素平方和的平方根；两个归一化向量的点积就是余弦相似度。

例如，选中30条策略、尝试相隔一个交易日时，每边都展开为19 × 30，即570个数。双方共有的收益位置贡献相似性，单方缺失填零的位置会影响相似度大小。

对每个查询日期，在当前 `gap` 下选取相似度最高的参考日期，并排除日期与自身匹配。最高分达到门槛，就记录关系并停止为该查询继续尝试更大的间隔；未达门槛则继续增加 `gap`。因此，这里优先接受较短间隔的合格匹配。

参考日期按整批参与比较，查询日期按 `batch_size` 分批计算；`batch_size` 默认128，控制每批查询的数量。

第一次匹配用于寻找后继。仍未匹配的查询日期，再将历史顺序反转后寻找前驱，并通过 `reverse=True` 调整结果方向，始终把较早日期放在左边。

每个市场都执行上述步骤，最后返回所有市场生成的日期关系。

### 6.4 CalendarEdge：保存一条关系

`CalendarEdge` 的字段如下：

| 字段 | 含义 |
|---|---|
| `left` | 较早的匿名日期编号 |
| `right` | 较晚的匿名日期编号 |
| `group` | 用哪个市场的交易日历计算间隔 |
| `gap` | 相隔的市场交易日数 |
| `confidence` | 本次匹配的余弦相似度 |

例如，一条关系可以表示“乙比甲晚两个日本交易日”。这里确定相对位置，具体真实日期由候选集合继续约束。

## 7. add：合并日期关系与候选方案

`recover()` 对日期关系按交易日间隔从小到大排序，同一间隔内按置信度从高到低排序，再依次调用 `forest.add(edge)`。

### 7.1 shift_map：将左边候选按交易日移动

`shift_map(group, gap)` 构造一个按自然日下标查询的数组，给出在指定市场移动 `gap` 个交易日后的自然日下标。休市日或移动后超出范围的位置记为 `-1`，结果按市场与间隔缓存。

例如，某市场周五后移一个交易日，结果可以是下周一。这一步通过市场交易日下标计算，跨过周末和当地休市日。

`add()` 将查询数组应用到左边匿名日期的全部候选，得到 `shifted`。它保存每个左边候选要求右边对应的自然日下标。

### 7.2 两个日期已经属于同一关联组

同一组的每列已经是一套共同方案，因此直接比较 `shifted` 与右边匿名日期同列的候选是否相等。

一致的列保留，不一致的列删除。如果所有列都不成立，拒绝本条关系，原有关联组保持不变。

### 7.3 两个日期属于不同关联组

先寻找左右候选能配对的位置，再取出对应的整列方案。

下面用一个简化日历说明数组操作。设自然日下标为0到9，这些位置在本例中均视为开市日；最后一个位置后移一个交易日超出范围。甲、乙、丙、丁的匿名日期编号依次为0、1、2、3。

左边关联组 `left` 包含甲、丙，右边关联组 `right` 包含乙、丁：

```python
left = {
    0: np.array([4, 5, 7, 9]),  # 甲
    2: np.array([3, 4, 6, 8]),  # 丙
}
right = {
    1: np.array([0, 5, 8]),  # 乙
    3: np.array([1, 6, 9]),  # 丁
}
```

新关系要求乙比甲晚一个交易日，于是甲的候选移动后为：

```python
shifted = np.array([5, 6, 8, -1])
```

我们创建反向查询数组 `inverse`，将右边候选的自然日下标映射到其候选位置：

```python
inverse = np.full(10, -1, dtype=np.int64)
inverse[right[1]] = np.arange(len(right[1]))
# [0, -1, -1, -1, -1, 1, -1, -1, 2, -1]
```

例如，日期下标5是乙的第1号候选，所以 `inverse[5]` 为1；日期下标6不在乙的候选中，所以返回 `-1`。

`right_positions` 保存每个左边候选对应的右边候选位置，`keep` 标记配对是否有效：

```python
right_positions = inverse[shifted.clip(min=0)]
# [1, -1, 2, 0]

keep = (shifted >= 0) & (right_positions >= 0)
# [True, False, True, False]
```

`clip(min=0)` 临时把负下标改成零，避免将 `-1` 当作访问数组末尾；随后通过 `shifted >= 0` 排除原本无效的移动结果。

取出有效位置后：

```python
left_positions = np.flatnonzero(keep)
# [0, 2]

right_positions = right_positions[keep]
# [1, 2]
```

`left_positions` 表示保留的左边候选位置。因此，左边第0号方案配右边第1号方案，左边第2号方案配右边第2号方案。

按这些位置从两边每个成员的数组中取值，再合并成 `merged`：

```python
merged = {
    0: np.array([4, 7]),  # 甲
    2: np.array([3, 6]),  # 丙
    1: np.array([5, 8]),  # 乙
    3: np.array([6, 9]),  # 丁
}
```

合并过程保留整列方案，所以甲、丙原有的关系以及乙、丁原有的关系同时得到保留。

### 7.4 检查合并方案中的日期重复

合并时，我们要求同一关联组内不同匿名日期对应不同真实日期：

```python
dates = np.sort(np.stack(list(merged.values())), axis=0)
distinct = (np.diff(dates, axis=0) > 0).all(axis=0)
```

这里的 `dates` 是检查用的二维数组：先把所有成员的候选数组叠起来，再分别对每列排序。`np.diff()` 对每列相邻值做差；某列存在重复日期时，至少有一个差为零。

`distinct` 标记每一列是否不存在重复。本例得到 `[True, True]`，两套方案都通过；若得到 `[False, True]`，就从所有成员数组中共同删掉第0列。没有任何方案通过时，拒绝这条关系。

### 7.5 更新 components 与 owners

假设合并前左边组编号 `left_owner` 为0，右边组编号 `right_owner` 为1：

```python
self.components[left_owner] = merged
del self.components[right_owner]
self.owners[list(right)] = left_owner
```

第一句把合并结果写入第0组；第二句删除原第1组；第三句将右边所有成员的所属组改为0。

本例中 `list(right)` 为 `[1, 3]`，即乙、丁的编号。因此，按甲、乙、丙、丁排列的 `owners` 从 `[0, 1, 0, 1]` 变成 `[0, 0, 0, 0]`。

成功接收关系后增加 `accepted` 并返回 `True`；拒绝时增加 `rejected` 并返回 `False`。

## 8. 返回候选映射与恢复统计

全部关系处理完成后，`forest.domains()` 按匿名日期编号取出各日期剩余的候选自然日下标。

`recover()` 用 `calendar` 将下标转回真实日期字符串，组成 `mapping`。以下是输出结构示例：

```json
{
  "DATE_0001": ["2013-07-26"],
  "DATE_0011": ["2001-05-16", "2001-08-29"]
}
```

一个候选表示唯一定位，多个候选表示仍有多套方案。关联组内日期的相对间隔可以已经确定，但整个组仍可能落在多段真实时间上。

`report` 返回以下统计和过程说明：

| 字段 | 含义 |
|---|---|
| `dates` | 参与恢复的匿名日期总数 |
| `uniquely_resolved_dates` | 最终只有一个候选的匿名日期数量 |
| `query_dates` | 官方测试匿名日期数量；未传入测试记录时为零 |
| `unique_query_dates` | 官方测试匿名日期中唯一定位的数量 |
| `accepted_edges` | 接受的日期关系数量 |
| `rejected_edges` | 拒绝的日期关系数量 |
| `reference_pool` | 默认使用训练日期的历史特征作为匹配参考 |
| `uses_targets` | 是否使用目标收益标签，本步骤为 `False` |

本模块返回 `mapping` 与 `report`，由调用方接收和保存。官方测试集的后续候选筛选与行情评分在 `calendar_alignment.py` 处理。
